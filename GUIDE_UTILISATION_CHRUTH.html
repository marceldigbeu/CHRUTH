1. Démarrage rapide

Tout le projet s'utilise depuis une seule porte d'entrée :

  1. Ouvrir le dossier du projet (CHRUTH_LIVRAISON_NO_CODE).
  2. Double-cliquer sur COCKPIT_CHRUTH.bat.
  3. Une fenêtre noire s'ouvre (la laisser ouverte), puis le navigateur affiche le cockpit CHRUTH.
Premier lancement : le fichier vérifie que Python est installé et installe tout seul les dépendances (connexion internet nécessaire une fois). Si Python manque, il affiche le lien de téléchargement — installer en cochant « Add python.exe to PATH », puis relancer.

Prérequis : Windows, Python 3.10 ou plus récent, Excel (pour les classeurs .xlsm, macros autorisées), internet pour les collectes de données et la carte.

2. Configurer ses clés (IA et Gmail)

Le projet fonctionne sans aucune clé : les messages utilisent alors des modèles de texte prédéfinis. Les clés servent à deux choses : rendre les messages personnalisés par IA, et envoyer des emails depuis l'interface.

2.1 Clé IA — activer les brouillons personnalisés

Une seule clé suffit, au choix parmi quatre fournisseurs. Où l'obtenir :

FournisseurOù créer sa cléLigne à remplir dans .envRemarque
Anthropic (Claude)console.anthropic.com → Settings → API KeysANTHROPIC_API_KEY=Payant à l'usage, très bonne qualité
Mistralconsole.mistral.ai → API KeysMISTRAL_API_KEY=Acteur français, offre gratuite limitée
Groqconsole.groq.com → API KeysGROQ_API_KEY=Gratuit avec quotas, très rapide
Google Geminiaistudio.google.com/apikey → « Create API key » (compte Google suffit)GEMINI_API_KEY=Gratuit avec quotas généreux — le plus simple pour démarrer

Mise en place, pas à pas :

  1. Créer la clé sur le site du fournisseur choisi (elle ressemble à sk-ant-…, gsk_… ou AIza… pour Gemini). La copier immédiatement : certains sites ne la réaffichent plus ensuite.
  2. Ouvrir le fichier .env à la racine du dossier projet, avec le Bloc-notes (clic droit → Ouvrir avec → Bloc-notes). S'il n'existe pas, copier .env.template et renommer la copie en .env.
  3. Coller la clé juste après le = de la ligne correspondante, sans espace ni guillemets. Exemple : 
    GEMINI_API_KEY=AIzaSyD4xxxxxxxxxxxxxxxxxxxxxxxx
  4. Enregistrer le fichier et relancer le cockpit. Le moteur détecte la clé tout seul : rien d'autre à régler.
Si plusieurs clés sont présentes, l'ordre de priorité est : anthropic > mistral > groq > gemini. Sans aucune clé, le moteur essaie Ollama (IA locale, si installée), sinon il utilise les modèles de texte prédéfinis — tout continue de fonctionner. Le bandeau d'alertes du cockpit indique si une clé est détectée.
Important — la fiche CHRUTH. Pour que l'IA écrive des messages précis et n'invente rien, remplir une fois config_chruth/fiche_chruth.md (ouvrable depuis l'onglet Livrables) avec des faits vrais : activité, zone d'intervention, prestations, points forts, et ce qu'il ne faut PAS prétendre. Tant que la fiche est vide, les messages restent volontairement génériques.

2.2 Changer ou révoquer une clé IA

  1. Sur le site du fournisseur, supprimer (révoquer) l'ancienne clé si besoin et en créer une nouvelle.
  2. Rouvrir .env, remplacer l'ancienne valeur par la nouvelle, enregistrer, relancer le cockpit.

2.3 Gmail — envoyer des emails depuis l'interface

L'envoi utilise un mot de passe d'application Gmail (16 caractères), différent du mot de passe du compte.

  1. Activer la validation en 2 étapes sur le compte Google (obligatoire pour la suite) : myaccount.google.com → Sécurité.
  2. Créer le mot de passe d'application : myaccount.google.com/apppasswords → donner un nom (ex. « CHRUTH ») → copier les 16 caractères affichés.
  3. Dans le cockpit, onglet 4. Email : renseigner l'email expéditeur Gmail, coller le mot de passe d'application, renseigner le destinataire, cliquer Enregistrer.
  4. Générer un message (onglet 2 ou 3), cliquer « Envoyer par email → », vérifier le sujet et le corps, puis Envoyer l'email.

Pour changer ce mot de passe : en recréer un sur myaccount.google.com/apppasswords, puis le recoller dans l'onglet Email → Enregistrer. Il est stocké localement dans alertes_secrets.json (jamais copié dans les packs ni sur GitHub).

2.4 Alertes automatiques GitHub Actions (optionnel)

Si le dépôt GitHub est utilisé pour les alertes AO horaires, les clés se règlent dans GitHub : Settings → Secrets and variables → Actions → renseigner CHRUTH_SMTP_USER, CHRUTH_SMTP_PASSWORD et CHRUTH_ALERTE_DEST. La variable CHRUTH_NOTIFICATIONS=OFF suspend les envois sans toucher au code.

3. Le cockpit web, section par section

État des missions

En haut du cockpit : les 4 missions de la fiche de poste + l'extension appels d'offres, chacune avec ses livrables en vert (présent, avec date et taille) ou rouge (manquant). Se met à jour automatiquement après chaque génération. Le bandeau jaune signale ce qui reste à faire (fiche CHRUTH, clé IA).

1. Générer

Le bouton « Générer tous les documents » régénère l'ensemble des livrables. Les cases à cocher :

OptionEffetDurée
Recollecter les appels d'offres BOAMP/DCEVa chercher les nouveaux marchés publics sur internet~2 min
Recollecter les prospects API EntreprisesRecollecte toute la France (~43 000 établissements)Longue (dizaines de minutes)
Générer les brouillons IARédige les messages avec l'IA (si clé configurée)Variable
Créer le dossier portableCopie prête à envoyer, sans les secretsRapide
Mode recommandé au quotidien : ne rien cocher. La pipeline retraite les données déjà présentes et régénère tous les fichiers en quelques minutes, sans internet. Le journal noir affiche la progression en direct.

Les deux autres boutons : « Mettre à jour les AO seulement » (collecte BOAMP + cockpit AO) et « Messages prospects dans Excel » (régénère le classeur de messages).

2. Messages prospects

  1. Cliquer « Charger les segments » : la liste des segments CHAUDE/TIÈDE apparaît (ex. IMMO_AGENCE — CHAUDE).
  2. Choisir un segment ; un exemple réel (dénomination, ville, effectif) se remplit tout seul — modifiable.
  3. Cliquer « Générer email + script » : l'email et le script d'appel s'affichent côte à côte.
  4. Boutons : copier l'email, copier le script, ou « Envoyer par email → » qui bascule le texte dans l'onglet Email.

3. Messages AO

Même logique pour les appels d'offres : « Charger les AO chauds/tièdes » (classés par score décroissant), choisir un AO (ses détails s'affichent : objet, acheteur, date limite, budget, lien de l'avis), puis « Générer email + script AO ». Pour retravailler un AO en profondeur, utiliser le notebook CHRUTH_Messages_AO.ipynb (onglet Livrables).

4. Email

Configuration Gmail (voir section 2.3) et envoi du message affiché. Le sujet est extrait automatiquement de la ligne « Objet : » du message généré.

5. Livrables

Tous les fichiers du projet ouvrables en un clic, classés en 5 groupes : livrables principaux, exports (Power BI, Notion, KPI), messages & IA, guides & documentation, notebooks & avancé. Un point vert = le fichier existe.

6. En cas de problème

  • « Rien ne se met à jour » : un classeur Excel est resté ouvert → Excel verrouille le fichier. Fermer Excel et relancer (les boutons intégrés aux classeurs gèrent cela tout seuls).
  • Le cockpit ne s'ouvre pas : vérifier que la fenêtre noire est bien restée ouverte ; sinon relancer COCKPIT_CHRUTH.bat. Si le navigateur ne s'ouvre pas seul, taper http://127.0.0.1:8770 dans la barre d'adresse.
  • Erreur pendant une génération : ouvrir le fichier le plus récent du dossier logs/ (accessible depuis l'onglet Livrables) — la dernière ligne indique la cause.
  • Les messages IA restent génériques : soit la fiche CHRUTH est vide (section 2.1), soit aucune clé n'est détectée (vérifier le bandeau d'alertes du cockpit).
  • L'email ne part pas : vérifier que c'est bien un mot de passe d'application (16 caractères) et non le mot de passe du compte, et que la validation en 2 étapes est active.
  • La carte est vide : elle a besoin d'internet à l'ouverture (fonds de carte OpenStreetMap). Après une régénération, faire Ctrl+F5 pour recharger.
  • Collecte désactivée : les boutons « Activer / Désactiver collecte » des classeurs pilotent un mode hors-ligne (état OFF = aucun appel internet, retraitement local seulement).

7. Sécurité des clés

  • Les clés vivent dans deux fichiers locaux : .env (clés IA) et alertes_secrets.json (Gmail). Les deux sont dans le .gitignore : ils ne partent jamais sur GitHub ni dans les packs générés.
  • Le cockpit n'est accessible que depuis l'ordinateur lui-même (127.0.0.1) — personne sur le réseau ou internet ne peut s'y connecter.
  • Toute personne qui ouvre la session Windows peut en revanche utiliser les clés enregistrées : la protection est celle de la session.
  • Si le dossier est partagé à la main (clé USB, WeTransfer…), supprimer .env et alertes_secrets.json de la copie — ou utiliser l'option « Créer le dossier portable » qui les exclut automatiquement.
  • En cas de doute sur une clé (fuite, partage involontaire) : la révoquer sur le site du fournisseur et en créer une nouvelle (sections 2.2 et 2.3).
